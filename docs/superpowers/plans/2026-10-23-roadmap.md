# Sports Slot Booking — Implementation Roadmap

**Spec:** `docs/superpowers/specs/2026-10-23-sports-slot-booking-design.md`

The spec covers many subsystems. Each row below is its own implementation plan that ends in working, tested software. Plans are written one at a time, just before they are built, so each can use the exact names and signatures the previous plans actually produced. Order matters: each plan depends only on plans above it.

## App-wide failure modes every plan must keep in mind

1. Two concurrent requests for the same slot → exactly one succeeds, other gets `409`.
2. A manager/staff request for another owner's (or unassigned venue's) data → `404`, never data.
3. Slot times around midnight and DST changes in the venue's timezone → slots generated in venue local time, stored UTC, never duplicated or skipped silently.
4. Stripe webhook delivered twice or out of order → booking/payment state applied once.
5. Money in zero- or three-decimal currencies → no float math anywhere; integers in minor units.
